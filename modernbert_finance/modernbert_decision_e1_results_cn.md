# ModernBERT 决策模型 E1 结果

日期：2026-09-26
Kaggle Kernel：`smmt315/modernbert-decision-e1-a-b-c-gpu-experiment`
状态：E1 复验完成；不据此启动全量训练

## 实验配置

- Kaggle Tesla T4，ModernBERT 随机初始化，hidden size 256、4 层、4 heads
- 冻结 Kronos tokenizer；权重 SHA-256 与预期一致
- 训练抽样 4,096 条，验证抽样 2,048 条；每组 3 epochs、192 optimizer steps
- A：s1/s2 金融 token + 市值百分位/行业
- B：学习型 mask 序列 + 市值百分位/行业
- C：仅市值百分位/行业条件
- 三组共享样本、初始化种子、batch size 64 和优化配置
- 每条抽样记录均校验了 symbol、as-of 日期及未来 10 日 MFE/MAE 标签

## 首次 E1 指标

| 输入 | Validation macro log loss | Macro Brier | Macro ECE (10 bins) | Median step |
|---|---:|---:|---:|---:|
| A：token + 条件 | 0.598747 | 0.205972 | 0.043777 | 0.0274 s |
| B：mask + 条件 | 0.602648 | 0.207674 | 0.041219 | 0.0262 s |
| C：仅条件 | 0.598999 | 0.206105 | 0.037160 | 0.0175 s |

首次单 epoch 结果不足以证明金融 token 有稳定增益，因此又进行了 3 seed
复验。

## E1 复验指标

| 输入 | 3 seed 平均 macro log loss | seed 标准差 | 3 seed 平均 macro Brier | 3 seed 平均 macro ECE |
|---|---:|---:|---:|---:|
| A：token + 条件 | 0.594422 | 0.002204 | 0.204237 | 0.044007 |
| B：mask + 条件 | 0.595259 | 0.001326 | 0.204739 | 0.036520 |
| C：仅条件 | 0.596619 | 0.002576 | 0.205192 | 0.041848 |
| 常数验证集先验 | 0.592827 | - | 0.203636 | 0.000000 |

A 相对 C 的平均 log loss 改善约 0.002197，平均 Brier 改善约 0.000955，
但 A 仍劣于常数先验基线，说明当前训练预算下模型尚未提取出可用的概率
信号。A 的校准误差也高于 B/C 和常数基线。

## 修正时间切分后的复验

修正后不再排除与验证集重叠的股票，而是使用完整的历史训练时间段。3 seed
平均结果如下：

| 输入 | 平均 macro log loss | 平均 macro Brier | 平均 macro ECE |
|---|---:|---:|---:|
| A：token + 条件 | 0.598402 | 0.205943 | 0.050145 |
| B：mask + 条件 | 0.597081 | 0.205462 | 0.039663 |
| C：仅条件 | 0.599482 | 0.206417 | 0.044689 |
| 常数验证集先验 | 0.592827 | 0.203636 | 0.000000 |

修正后 A 相对 C 有约 0.001080 的 log loss 改善，但仍明显劣于常数先验；
B 在本次小预算下反而优于 A。结论仍然是训练链路可行，但金融 token 尚未
证明具有稳定、可用的增量价值。

## 零初始化门控 token 复验

为避免金融 token 的随机初始化一开始破坏市值/行业条件，增加了零初始化
`market_gate`，并与 C 使用相同的 16,384/8,192 样本、5 epochs、3 seeds。

| 输入 | 平均 macro log loss | 平均 macro Brier | 平均 macro ECE |
|---|---:|---:|---:|
| A_gated：门控 token + 条件 | 0.591066 | 0.203028 | 0.040237 |
| C：仅条件 | 0.592206 | 0.203410 | 0.021243 |
| 常数验证集先验 | 0.594293 | 0.204160 | 0.000000 |

门控 token 版本首次同时超过了 C 和常数先验的 log loss/Brier，说明 token
分支可能确实包含增量信息。但 ECE 仍明显高于 C，且验证样本仍是随机抽样，
因此还不能直接进入全量训练。下一步应使用按日期分块的验证集确认增益是否
稳定，再进行更大规模训练和温度校准。

## 按时间分块复验

第 7 版将验证集拆成 2025 年下半年和 2026 年上半年。3 个 seed 的平均
macro log loss：

| 时间段 | A_gated | C | A_gated 相对 C |
|---|---:|---:|---:|
| 2025H2 | 0.571062 | 0.567277 | +0.003786 |
| 2026H1 | 0.611775 | 0.618014 | -0.006239 |

这说明门控 token 的增益存在明显的时间依赖：在早段验证中落后，在晚段验证
中领先。整体提升不能视为稳定跨市场状态增益，但它支持继续做带时间验证和
校准的全量训练试验。全量训练必须保存按日期的验证曲线，并以时间后段指标
和校准指标共同选择 checkpoint。

## 数据审计发现与修正

面板和标签文件 SHA-256 均与 sidecar manifest 一致。审计发现训练与验证面板的
symbol 集合交集为 **511**，训练/验证 target 中也有 **511** 个重复 symbol。
进一步检查这些股票的日期后确认：训练 panel 到 2024-12-31 截止，验证 panel
从 2025-01-02 开始；训练标签截止 2024-12-31，验证标签从 2025-07-03 开始。
因此这是时间切分，不是未来数据泄露。

第一次复验为了强行模拟 symbol holdout，排除了这些股票，导致训练样本偏离
数据集真实设计。后续复验应恢复全部训练窗口，以评估“历史训练 -> 未来验证”
的时间泛化能力。`symbol_intersection: 0` 这一字段的含义或生成逻辑仍应修订，
避免把该数据集误读为严格股票隔离。

## 决策

**暂不进入 E2 全量训练。** 当前已经证明 GPU 训练链路和 token 输入可以运行，
但没有证明模型超过简单先验基线。下一步先修正 symbol/time split 契约，并在
正确的时间切分上增加训练样本、训练预算和校准评估。只有 A 在严格验证中
稳定超过常数先验和 C，才扩大到 E2 全量训练。

本次 Kaggle E1 没有重新上传 OHLCVA、完整窗口或 tokenized 数据集；仅在 Kernel
工作目录产生小样本 token cache。
