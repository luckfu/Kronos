## 判定与后续

第一轮训练完成，但**概率质量验收未通过**。暂不把 `final_model.pt` 称为
可用于仓位或开关决策的模型，也暂不自动启动第二轮八段训练。
目前不能仅凭汇总指标判断根因是分布漂移、优化过程、推理实现还是其他问题。

需要注意训练日志口径：训练时记录的是上下两组四头 BCE 的和，不能直接与验证
阶段八个头的平均 log loss 比较。即便将训练 loss 除以 2，当前训练/验证鸿沟
仍然很大，不能用口径差异解释失败。

在继续消耗第二轮 GPU 配额前，按以下优先级审计：

1. **同批次训练/推理对照**：固定同一小批样本，逐项对比训练模式和验证模式的
   history、s1/s2 token、sector、size、labels、logits、sigmoid 概率和 loss；
   同时检查 `model.train()`/`model.eval()`、autocast 和 tokenizer 冻结状态。
2. **标签人工复核**：抽取若干 `down_012=1` 和 `down_012=0` 样本，人肉用原始
   OHLCVA 计算未来 10D `MAE10`，并复核 `up_012`，确认阈值、方向、窗口端点和
   `start_index` 没有错位。
3. **训练集基线**：用训练集正例率构造固定常数基线，在完整验证集以及
   `2025H2`/`2026H1` 上比较 8 个头的 log loss、Brier 和 ECE；不能用验证标签
   拟合后再把该结果当作部署基线。
4. **区分排序与校准**：为 8 个头补充 ROC-AUC 和 PR-AUC，结合 per-threshold
   reliability 分桶，判断是排序能力失败还是仅概率尺度失真；只有排序仍有救时
   才进入温度缩放评估。
5. **规模化回归审计**：逐项对比 E1 与全量训练的配置差异，包括验证集构成、
   数据顺序、chunk 接力、checkpoint/optimizer 恢复、模型尺寸、batch、学习率、
   AMP 和训练步数，优先定位为何 E1 接近常数而全量明显恶化。
6. 在上述问题有结论后，才在独立开发/校准分割上评估温度缩放，并与最终评估
   样本严格隔离。
7. 确认质量门槛后，才按既定 Round 2 seed、分段验证和单任务接力计划启动。

不得用最终验证集的标签拟合温度，也不能把事后验证先验当作实盘基线。

## P1 训练先验与排序审计结果

2026-09-29 的 `wynstonliu/kairos-r1-metrics-audit` V2 已完成，覆盖训练集
`9,010,965` 条和验证集 `123,836` 条。训练集 64 条标签、验证集 16 条标签
均通过原始 OHLCVA 现场复核，并通过 T/T+1 边界检查；输出单调性违反数为 0。

全体验证集的训练先验常数基线为：

```text
macro log loss = 0.5966
macro Brier    = 0.2052
```

模型仍为：

```text
macro log loss = 0.9182
macro Brier    = 0.2700
```

因此模型不仅没有超过训练集先验，而且明显更差。排序指标也不支持“只是
温度失真”的解释：全体 8 头 ROC-AUC 为 `0.493..0.622`，其中 `up_003`
约 `0.505`、`up_005` 约 `0.514`，只有 `down_012` 达到约 `0.622`。
PR-AUC 需结合各头正例率解释，不能单独与 0.5 比较。

时间分块显示排序信号不稳定：2025H2 的 `down_012` ROC-AUC 约 `0.757`，
但 2026H1 降至约 `0.610`；多数上行头接近随机。当前证据表明模型存在
局部、时间依赖的排序信号，同时概率输出严重失真，暂不进入温度校准或 R2。
