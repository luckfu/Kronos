# Wave 2 / Wave 3 十二月上旬封存复核事前登记标准（分体制验收协议，2026-11-25）

> **防泄漏与纪律声明**：本协议在 `2026-11-25`（十二月上旬复核窗尚未到期前）冻结，用于规范下一轮 `D10 / D5` 封存复核及生产融合头切换裁定。所有参评模型的底座权重、PCA 基、岭回归头、3-seed 神经网络与 LightGBM 均严格冻结自 **`<= 2026-07-02`**（65 天 OOS 筛选截止 `2026-10-23`），复核全程**零重训、零调参、零权重再拟合**，所有跨成员融合严格采用**等权横截面秩平均**。

## 1. 修订背景与核心审视

在首轮封存验收窗（`2026-10-26 .. 2026-11-20`，详见 `finetune/reports/20261123_sealed_acceptance_w2w3_result_cn.md`）中，全球风险资产遭遇剧烈抛售与流动性踩踏，A 股市场在 `2026-11-04 .. 2026-11-20` 出现罕见的 V 型反转（`breadth_ma20` 先冲高至 `57.2%` 后骤降至 `8.6%`，10 日全市场等权均值 `-8.44%`）。首轮窗主评估期 `D10` 仅包含 `3` 个 `G_BREADTH >= 30%` 实盘开仓日，存在两项统计局限：

1. **单一总均值易被极端反转日主导**：用 `3` 个极端踩踏日直接否定 65 天 OOS 的排序结论，统计检验力不足；但直接剔除极端样本又会掩盖模型在流动性挤兑期的脆弱性（例如短窗 `G32_C2_L45_AR16` 在 `D10` 被均值回归剧烈反噬）。

2. **首轮窗已拆封，后续复核需防止“事后消融过拟合”**：首轮报告 4.2 节基于事后消融提炼了剔除 `G32_C2_L45_AR16` 后的 `C2 + G27/G30` 候选组合。十二月上旬复核必须将**纯新增未拆封样本**与**累计跨体制样本**分开考核，避免候选组合借首轮已知样本“吃老本”。

因此，本协议确立“前置硬门槛 + 双层时间口径 + 常态/极端分体制加权（65% / 35%）”的验收框架。

## 2. 双层时间口径与最小样本门槛

### 2.1 双层评估口径

复核时必须同时输出以下两套独立口径，且均基于 Oracle 生产库 `public.ashare_daily_k` × `public.ashare_adj_factor` 与线上 `/opt/kronos-web/data/prediction_shadow/<date>/full_market/ranking.csv`：

| 口径名称 | 信号日（`asof`）范围 | 定位与防污染作用 | 
| ----- | ----- | ----- | 
| **口径 A · 纯增量未拆封窗（Primary Strict Sealed）** | `asof >= 2026-11-09` 且已满 10 个交易日到期 | **100% 未拆封新样本**，用于对首轮事后消融提炼的新组合做严格零前视检验 | 
| **口径 B · 累计跨体制窗（Cumulative Multi-Regime）** | `asof >= 2026-10-26` 起的全部 `D10` 到期日 | 合并 11 月极端暴跌期与 11 月下旬–12 月上旬修复/常态期，用于执行分体制加权总评 | 

> 扩展窗口 `D5` 同步按上述双层口径输出（口径 A 起始日为 `2026-11-16` 起的新增到期日，口径 B 为 `2026-10-26` 起的累计到期日），用于核验短长周期一致性。

### 2.2 前置硬门槛与自动顺延机制（一票否决）

未同时满足以下三项前提时，**不得执行生产换头裁定**：

1. **生产一致性门禁（Parity Gate）**：在复核截止日全市场截面上，离线推理复现当前线上 `deploy/oracle-kronos/head_val_alpha1e4.npy` 的结果与线上 `ranking.csv` 逐股比对，要求 `score_hidden` 与 `score_fused` 的 Pearson 相关系数均 **`> 0.9999`**。

2. **最小有效样本量**：

   * 口径 B 累计 `D10` 到期信号日 **`>= 20` 个交易日**；

   * 口径 A 纯增量 `D10` 到期信号日 **`>= 10` 个交易日**；

   * 口径 B 中归属“常态开仓期”的 `D10` 信号日 **`>= 8` 个交易日**。

3. **自动顺延规则**：若至 `2026-12-11` 收盘时，受连续弱市影响导致常态开仓日仍不足 `8` 天，则**自动顺延至首个满足上述样本门槛的交易日**再执行一次性正式裁定，严禁在样本不足时提前主观拍板。

## 3. 客观体制划分规则（明确区分事前门控与事后分层）

为避免实盘逻辑与评估口径混淆，严格区分以下两类变量：

* **事前因果门控变量（实盘可用）**：信号日 `asof` 当日收盘可因果计算的 `breadth_ma20`（全市场有效交易股中复权收盘价高于 MA20 的占比，沿用线上 `< 0.30` 空仓防御、`>= 0.30` 开仓运行规则）。

* **事后冲击分层标签（仅用于历史评估分组，严禁进入模型特征或实盘信号）**：基于每个信号日 `asof` 对应 10 日持仓窗 `[asof, target_d10]` 内实际发生的市场环境，将所有 `D10` 信号日划分为三个互斥层：

| 体制层 | 客观判定公式（可直接在评测脚本中编程实现） | 实盘对应状态 | 复核考核定位 | 
| ----- | ----- | ----- | ----- | 
| **常态开仓期（Normal Active）** | `breadth_ma20(asof) >= 0.30` **且** 持仓 10 日全市场等权均值 `univ_ret_d10 ∈ (-0.05, +0.08]` **且** 持仓窗内任意连续 5 个交易日宽度变化 `min Δbreadth_5d > -0.20`（20 个百分点） | 实盘开仓运行 | **65% 权重**，考核常态 Alpha 上限与稳定性 | 
| **极端开仓期（Extreme Active）** | `breadth_ma20(asof) >= 0.30` **且**（`univ_ret_d10 <= -0.05` **或** `univ_ret_d10 > +0.08` **或** 持仓窗内存在连续 5 日宽度骤降 `min Δbreadth_5d <= -0.20`） | 实盘开仓期间遭遇系统性暴跌/踩踏或逼空 | **30% 权重**，考核抗流动性踩踏下限与风格中性韧性 | 
| **空仓防御期（Defensive）** | `breadth_ma20(asof) < 0.30` | 线上门控空仓规避 | **5% 权重**，仅作门控失效时的底层安全垫检验 | 

> 注：将 `univ_ret_d10 > +0.08` 同步归入极端开仓期，旨在防止单边情绪逼空行情扭曲常态期的选股排序评估；`min Δbreadth_5d <= -0.20` 的滑动窗口判定可精准捕获如 `11-04 .. 11-06` 这类“前 5 日急涨冲高、后 5 日急跌崩盘”的 V 型反转。

## 5. 分体制考核指标、代码口径与量化计分表（总分 100 分）

### 5.1 统一指标代码口径

所有指标均与现有脚本 `eval_sealed_acceptance_w2w3.py` 及 `fusion_analysis.py` 完全对齐：

* **原始 `Rank IC` / `ICIR`**：逐日横截面 Spearman 相关系数的均值及 `mean / std`；

* **行业市值反转中性化 `NIC`**：对实际收益执行 `fa.residualize(df, "actual_return", ["size_decile", "rev10"], sector=True)` 后再计算横截面 Spearman 相关系数；

* **实盘流动池超额 `liq10 / liq20`**：在 `med_amt_20d >= 5e4` 流动池内，每日选取打分前 `10` / 前 `20` 只标的等权收益减去流动池等权基准收益的均值。

### 5.2 分体制权重与计分规则

在口径 B（累计跨体制窗）上对每个候选方案按以下 8 项指标计分（每项按相对线上基线 `FUSE_VAL_1E4` 的表现评定：`1.0` = 明确胜出，`0.5` = 持平/小幅占优，`0.0` = 落后，单项得分 = 权重 × 档位系数）：

| 体制（总权重） | 考核指标 | 权重 | 满分（`1.0`）标准 | 持平（`0.5`）标准 | 不及格（`0.0`） | 
| ----- | ----- | ----- | ----- | ----- | ----- | 
| **常态开仓期（65）** | `D10` 原始 Rank IC 与 ICIR | **25** | 严格高于 `C2`，且 `IC >= FUSE_VAL_1E4` 且 `ICIR >= FUSE_VAL_1E4` | 严格高于 `C2`，且 `IC` 落后 `FUSE_VAL_1E4` 不超过 `0.003` 但 `ICIR` 更高 | 低于 `C2` 或 `IC` 落后 `FUSE_VAL_1E4` 超过 `0.003` | 
| **常态开仓期（65）** | 中性化 `NIC` | **15** | 严格高于 `FUSE_VAL_1E4` 与 `C2`（至少高 `+0.005`） | 高于 `C2`，且与 `FUSE_VAL_1E4` 差距在 `±0.005` 内 | 低于 `C2` 或落后 `FUSE_VAL_1E4` 超过 `0.005` | 
| **常态开仓期（65）** | 流动池超额 `liq10 / liq20` | **15** | `liq10` 与 `liq20` 均为正，且两者均值高于 `FUSE_VAL_1E4` 至少 `+0.50%` | 均为正且不低于 `FUSE_VAL_1E4` | 任一为负或低于 `FUSE_VAL_1E4` | 
| **常态开仓期（65）** | 胜率与 `D5` 一致性 | **10** | `D10` 与 `D5` 正 IC 天数占比均 `>= 70%` | 仅其一 `>= 70%` 且另一项 `>= 60%` | 任一项 `< 60%` | 
| **极端开仓期（30）** | 极端日 `liq10 / liq20` 下限 | **15** | 均高于 `FUSE_VAL_1E4` 且 `liq10 >= 0%`（无头部失血） | 高于 `FUSE_VAL_1E4` 且 `liq10 >= -1.0%` | `liq10 < -1.0%` 或弱于 `FUSE_VAL_1E4` | 
| **极端开仓期（30）** | 极端日中性化 `NIC` 韧性 | **10** | `NIC >= +0.05` 且高于 `FUSE_VAL_1E4` | `NIC > 0`（未退化为高波动反噬因子） | `NIC <= 0` | 
| **极端开仓期（30）** | 极端期 `D5` 抗反噬能力 | **5** | `D5` Rank IC `>= +0.05` 且不弱于 `C2` | `D5` Rank IC `> 0` | `D5` Rank IC `<= 0` | 
| **空仓防御期（5）** | 防御期（`< 0.30`）安全垫 | **5** | `D10` 原始 IC `>= 0` | `D10` 原始 IC `∈ (-0.02, 0)` | `D10` 原始 IC `<= -0.02` | 

### 5.3 红线否决项（触发任一条即禁止直接切换生产头）

1. **纯增量窗退化红线**：在口径 A（纯增量未拆封窗）中，`D10` 常态开仓期原始 Rank IC 落后 `FUSE_VAL_1E4` 超过 `0.010`，或 `liq10` 为负且弱于 `FUSE_VAL_1E4`；

2. **极端踩踏红线**：在口径 B 极端开仓期中，`liq10 < -1.5%` 或 `NIC <= 0`；

3. **短长周期冲突红线**：口径 B 极端开仓期 `D5` Rank IC `<= -0.02`（防止再次混入类似 `L=45 AR` 的反转脆弱组件）。

## 6. 最终换头裁定等级与工程落地路径

复核完成后，按以下三档输出唯一客观裁定结论：

1. **A 档 · 直接推进生产换头（Promote）**：

   * 通过全部前置硬门槛、未触发任何红线否决项；

   * 口径 B 综合得分 **`>= 80` 分**，且在口径 A（纯增量窗）的常态开仓期 `D10 IC`、`NIC`、`liq10` 均不弱于 `FUSE_VAL_1E4`（其中至少两项严格胜出）。

   * **同分/相近优选原则**：若两套达标方案总分差距 `<= 5` 分，**优先选择推理链路更轻量的方案**（优先级：`C2 + 轻量残差头` / `ENS_W2F_C2_MINI29` > 四家族重型集成），降低 Modal T4 延迟与线上维护复杂度。

2. **B 档 · 双轨影子灰度（Shadow / Canary）**：

   * 未触发红线否决项，口径 B 综合得分处于 **`65 .. 79.5` 分**（典型情形：中性化 `NIC` 与流动池 `liq10/20` 大幅领先 `FUSE_VAL_1E4`，但常态期原始 `Rank IC` 仅持平）。

   * **落地方式**：保留线上 `head_val_alpha1e4.npy` 主榜不变，在 `deploy/oracle-kronos/prediction_drill.py` 与 `/opt/kronos-web/data/prediction_shadow/<date>/` 中并行落盘候选打分列，在 WebUI 中开放对比切换，再观察 10 个交易日实盘表现后决定是否转正。

3. **C 档 · 维持现状（Hold）**：

   * 综合得分 `< 65` 分，或触发任一红线否决项。

   * **落地方式**：继续保持线上 `FUSE_VAL_1E4` 与 `G_BREADTH >= 30%` 门控原封不动，记录复核归因报告后进入下一轮研究迭代。
