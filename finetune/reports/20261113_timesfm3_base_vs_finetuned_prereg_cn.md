# TimesFM3：原始底座 vs 微调版（SweetSpot）对照 —— 事前登记（2026-11-13，跑数之前写定）

## 要回答的问题

TimesFM 这条线此前只比过“微调后的不同检查点之间”，从没比过“训练前 vs 训练后”。
本轮补这一格：**在完全相同的 65 天、相同的输入通道上，官方底座 `google/timesfm-3.0-pytorch`
和微调后的 SweetSpot 差多少？微调到底有没有用？**

## 只做 B1（用户指定）

| 项 | B1 |
|---|---|
| 权重 | Hugging Face 公开底座 `google/timesfm-3.0-pytorch`，不挂任何 LoRA |
| 通道 0 | 收盘价（除以第 120 根收盘价） |
| 通道 1–5 | open / high / low / volume / amount，与微调版同样的归一化与截断 |
| 通道 6 | 市值分位（当日有成交股票的市值排名分位） |
| 通道 7 | 行业通道**整行为零**（`nn.Embedding` 权重初始化为全 0，不训练） |
| 其余 | 窗口构建、归一化、过滤、推理代码与 SweetSpot 那次**完全同一份** |

通道 7 置零是刻意的：底座没有行业嵌入（那是在训练脚本里外挂的模块），置零等于“给同样的
8 个通道，但不给行业信息”。这样两边的差别只剩下微调本身。
不做 B2（纯收盘价的 vanilla 用法）：用户指定只做 B1。

## 数据与分段

与 SweetSpot 新窗口评估完全相同：`luckfu/a-share-120d-oos-20260717-20261023-v2`，
65 个信号日、335,312 条；行业编号用 `symbol_split.csv` 的排序（虽然 B1 用不到，保持一致）。
标签取第 10 日收益。

| 段 | 信号日 | 天数 | 角色 |
|---|---|---|---|
| A | 2026-08-03 → 09-17 | 34 | 微调时用于挑选的窗口 |
| **B** | 2026-09-18 → 10-23 | 20 | **主判定段**：两个模型都没在上面挑选过 |
| C | 2026-07-17 → 07-31 | 11 | 补充 |

不读取 2026-10-24 之后的任何数据。

## 判定标准（B 段）

- **主判定**：SweetSpot 减 B1 的日度截面 Rank IC（逐日配对差），5 日块 bootstrap 2000 次，
  区间下界 > 0 记为“微调有效”，上界 < 0 记为“微调有害”，跨 0 记为“无法区分”。
- 同时报告（不设通过线）：方向正确率及其相对多数类基线的超额、平均绝对误差（对比预测 0）、
  A/B/C 三段各自的 IC、按排名分组（前 10、第 11–100、其余）的预测涨幅与实际涨幅。
- 一致性检查：两次运行的样本数必须都是 335,312，`input_patch_len`、`rolls`、
  `_stitching_extract_len`、`use_frozen_running_stats` 等超参必须一致（同一份代码、同一个底座架构）。
  若不一致，先查原因再解读。

## 事前预期

- 微调大概率带来一点排序能力：SweetSpot 在 A 段（它自己的挑选窗口）Rank IC 0.124，
  而底座没有在 A 股上训练过。
- 但两次的“绝对方向正确率”都会随行情漂移，看点应放在 IC 和“相对大盘”的指标上。
- 如果 B1 的 IC 接近 SweetSpot，那就说明微调的贡献很小，A 段那 0.124 主要来自这个底座本身的时序先验。

## 局限

1. 底座权重从 Hugging Face 在 kernel 内下载（公开仓库，无需凭据）；若下载失败，本轮作废重跑。
2. B 段只有 20 天，且是单边下跌行情。
3. 只测了 B1 一个口径；B2（纯收盘价）没有测，因此不能回答“协变量带来了多少”。
4. 底座的多变量输入方式（8 通道、通道 7 置零）是我们按微调版的约定拼的，不是底座的原生接口用法。
   若底座的 variate attention 对“全零通道”敏感，结果会受影响；这一点无法在不做 B2 的情况下区分。
