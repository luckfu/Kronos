# 按“准不准”重新看 TimesFM3：底座 vs 微调（2026-11-13）

前面的报告用的是 IC（截面排序）。用户的目的是**预测准确**，不是排序，所以这份用准确度口径重算。
数据与上一份完全相同（同一批 335,312 条、逐行配对），脚本
[`analyze_accuracy.py`](../timesfm3_v11_trajectory/eval_oos/analyze_accuracy.py)，
数字在 [`20261113_timesfm3_accuracy.json`](20261113_timesfm3_accuracy.json)。

## 1. 结论

**按“准”来衡量：两个模型都不准，而且在三段里有两段比不上“永远预测不涨不跌”。**

| 65 天合计 | 微调版 SweetSpot | 底座 B1 | 永远预测 0 |
|---|---:|---:|---:|
| 平均绝对误差（第 10 日） | **8.87%** | 10.42% | **7.32%** |
| 均方根误差 | 12.00% | 14.03% | 10.49% |
| 误差 ≤ 2% 的比例 | 15.1% | 12.7% | — |
| 误差 ≤ 5% 的比例 | 37.1% | 31.7% | — |
| 平均误差（预测减实际） | +0.50% | +5.91% | — |
| 与实际的相关系数（全样本合并） | 0.24 | 0.19 | — |

微调比底座准（误差低 1.55 个百分点、偏差从 +5.9% 收到 +0.5%），
**但仍然比“什么都不预测”差 1.55 个百分点。**

只有一段例外：7 月下旬那段大盘涨 7.8%，微调版误差 8.46% 低于零预测的 9.71%。
那一段“准”是因为**大盘在涨、而它预测大多数股票上涨**，不是因为算得准（见第 4 节）。

## 2. 三段分开看

| | A 挑选窗口 | B 新窗口 | C 7 月下旬 |
|---|---:|---:|---:|
| 大盘 10 日平均 | +0.68% | −5.13% | +7.81% |
| 微调：平均绝对误差 / 零预测 | 8.41% / 6.00% | 9.87% / 8.24% | **8.46% / 9.71%** |
| 底座：平均绝对误差 / 零预测 | 9.34% / 6.00% | 12.63% / 8.24% | 9.72% / 9.71% |
| 微调：误差 ≤5% 的比例 | 37.8% | 32.7% | 43.0% |
| 微调：符号命中 / 永远猜多数方向 | 58.6% / 52.3% | **51.0% / 75.6%** | 72.6% / 82.9% |

B 段最说明问题：大盘跌 5.1%、76% 的股票在跌，模型仍然预测 47% 的股票上涨，
符号命中 51%，等于抛硬币；而“永远猜跌”能到 75.6%。

## 3. 误差从哪来

把误差拆成“当日整体水平猜错”和“个股之间分错”：

| | 微调：水平 / 截面 | 底座：水平 / 截面 |
|---|---|---|
| A | 17% / 83%（水平误差 4.03%，截面 7.40%） | 13% / 87%（4.20% / 8.12%） |
| B | 18% / 82%（5.25% / 8.65%） | 39% / 61%（9.97% / 9.21%） |
| C | 4% / 96%（2.03% / 8.43%） | 13% / 87%（3.80% / 8.50%） |

**误差主要来自个股之间分不清**（占八成以上），不是大盘猜错。这跟 IC 低是同一件事：
这只股票未来 10 天涨 8% 还是跌 3%，模型给不出可信的差别。

底座在 B 段比较特殊：39% 的误差来自“整体水平”——它预测平均涨 4.8%，实际跌 5.1%，
一个系统性偏差就贡献了近 10 个百分点。

## 4. 预测幅度只兑现一小部分

把预测按幅度分组，看实际落在哪里（65 天合计，微调版）：

| 模型说 | 实际平均 | 实际上涨的占比 | 条数 |
|---|---:|---:|---:|
| −17% | −3.1% | 34% | 7,715 |
| −9% | −2.2% | 34% | 99,372 |
| −3% | −1.1% | 40% | 50,458 |
| +3% | −0.3% | 45% | 52,221 |
| +9% | +2.1% | 57% | 113,370 |
| +18% | +9.3% | 75% | 12,176 |

- **方向是对的，幅度差四五倍。** 预测 +9% 的股票实际平均 +2.1%；预测 −9% 的实际 −2.2%。
- 顺序也基本单调（除了最跌那一档反而好一点）。
- 事后拟合的最优缩放：微调版 ×0.27、底座 ×0.13。按这个缩放，误差才接近零预测
  （65 天：7.05% 对零预测 7.32%）。
- 换成“个股在当日的相对强弱”看，斜率只有 +0.16（微调）、+0.10（底座）：
  预测比当天平均高 1 个百分点，实际只高 0.16 个百分点。

## 5. 所以“让它准”意味着什么

要让它真正准，需要把预测幅度压到现在的四分之一左右，压完之后误差和“预测 0”持平。

换句话说：**在个股 10 日收益上，准确度的上限大约就是“不预测”。**
相关系数 0.19–0.24 看着不算零，决定系数约 4%–6%，但因为幅度放大了四五倍，
误差平方和反而比“预测 0”大 31%（微调）到 79%（底座）。把幅度压回正常水平，
剩下的那 4%–6% 才有一点意义，而那时误差与零预测持平。

这一点与 IC 的结论并不冲突：IC 说的是“排序有一点点用”，准确度说的是“绝对值几乎没用”。
排序只需要相对顺序，准确需要绝对值，后者难得多。

**可行的只有两种用法，都不需要它“准”：**
1. 只取排序，用来做相对比较（例如从候选里剔除最差的），不读预测数值；
2. 如果一定要一个数值，就用校准后的期望值（预测 × 0.27 左右），并且把它理解为
   “相对强弱的微弱指示”，而不是“这只股票会涨 9%”。

## 6. 局限

1. 一律是第 10 日；1–9 日的逐日结果在 JSON 的 `horizons` 里，趋势相同（误差随天数放大）。
2. 只在 2026-07-17 到 10-23 这一段上算，两段单边行情加一段震荡。
3. 事后最优缩放是在同一批数据上拟合的，只能当“上限诊断”，不能当可兑现的改进。
4. 底座 B1 的输入是我们按微调版约定拼的（行业通道置零），它的偏差里有多少源自这个，
   无法在不做 B2 的情况下区分。
